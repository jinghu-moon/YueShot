# 局部视觉结果优先发布：整素材跳框修正

## 问题与根因

事实：用户在T01左右矩形内部都选到整张素材，并观察到小框闪现后跳回。定向重编译解决了旧Release捕获库缓存不包含视觉模块的问题，但新程序的`capture.visual`日志仍显示BudgetExceeded／100ms stall，见[原始运行诊断](../visual-candidate-runtime-diagnostic/README.md)。不能仅以“默认已启用”解释为功能正常。

事实：`visual_progressive_distant_clutter_must_not_erase_a_local_target`在3840×2160源中生成512 ROI内的100×70完整实色框，远处为8px密集交替结构。修正前的失败日志为`before-distant-clutter.txt`：全源查询以BudgetExceeded退出，局部框无法使用。这是独立的自动化复现，不是用户桌面原图的完整还原。

根因推断与修正：`Query`虽然先持有512 ROI，却直接以全源coverage进行扫线与追边，并把整个外扩完成作为任何候选可用的前提。外围复杂度因此影响了局部清晰框。现在先在已持有ROI执行同一个A提案与原图四边验证，候选完整合格才发布，再继续原全源查询。外扩失败不会否定已验证局部框。

## 关键行为与边界

| 项目 | 修改前 | 修改后与验证 |
| --- | --- | --- |
| 局部清晰框＋远处复杂结构 | 等待全源完成；超预算后回退原生容器 | 先发布完整局部候选；真实GPU／worker回放中，失败外扩排空后仍保持小框；换点重新验证 |
| 原生大容器晚到 | 没有视觉结果时只能显示大容器 | 控制器回放注入晚到Unknown大容器，预览和确认仍为小框；Text/Image具体语义保护不变 |
| ROI边缘证据不足 | 没有独立局部阶段 | 局部候选要求探针halo全部位于持有像素内：最大`3×4px`样本距离加双线性舍入为13px；ROI边不能替代源边。缺少halo的框等全源阶段复核 |
| 外层／大目标 | 完成后可提供外层链 | 保留原全源查询；完整外层结果追加，局部默认框优先，不因外层结果变大而自动跳框。若外扩失败，只保证已验证局部层，外层覆盖不足明确记录 |
| 过期源／鼠标／owner／确认 | 原gate拒绝旧结果 | 新Local回复与Step共用完整Key校验；换点清理局部框，确认后不能被继续扩展改写；原回放持续通过 |
| 时间／内存／颜色阈值 | 100ms stall、16MiB CPU容量守卫、4MiB atlas、1MiB追加读取预算 | 数值不变；可选外扩失败保留局部快照，无局部结果时仍按原策略失败；不提高阈值或发布未验证提案 |

仅新增同一worker的`Reply::Local`、`Work::Advance`和单个`Active::local_verified`位：前两者让owner在全源计算前先接收结果，后者区分“尚无可用结果”和“可选外扩失败”。去掉它们就会重新等待外围扫描或撤掉已验证框。不新增线程、缓存层、GPU shader、依赖、用户开关或兼容路径。

`Query::local`直接读取已有ROI字节，不申请额外像素图。局部与全源复用同一个提案／验证器；137条冻结查询中新增断言要求局部候选均属于完整参考结果，避免局部裁切凭空产生框。完整全源结果仍与原参考逐字段比较。

## 验证证据与范围

`summary.json`核对源码哈希与实际退出码：37项常规视觉测试、32项产品回放、5项owner生命周期和1项传输异常测试。`capture-regression.txt`为最终源码完整常规回归；忽略项单列，不计通过。旧批次在`../visual-candidate-local-first/`保留。

初次时延测试在Local先发布后触发旧测试的`calls > 0`断言：下一次请求仍属于正在扩展的同一点，被正确去重。原失败保留为`../visual-candidate-local-first/latency.txt`。测试改为每次先记录首个可用预览，再排空该次祖先查询后发新请求；没有删除或弱化断言，没有把缓存命中伪报为新查询时延。最终`latency.txt`仍以P95≤25ms、owner事件P95≤1ms、hot P95<0.1ms作门；样本量及适用输入见日志，不据此宣称真实宿主／满载／其他硬件达标。

`build-verification.json`核对最终EXE哈希、视觉／局部发布字符串、编译依赖与启动进程。仅普通构建命令退出0不足以证明旧缓存已被替换。

最终程序启动后的`runtime-events.json`已记录真实运行的`local_verified`与`fused origin=Some(Visual)`，包括外扩BudgetExceeded后的Visual融合；这确认产品实际采用了视觉来源。日志不包含目标几何或最终导出内容，因此不替代用户对选框尺寸、稳定性和保存结果的可见验收。

真机F5/F7／保存／贴图及真实宿主资格继续由用户后续验收。本次不把离线／GPU回放当作用户桌面上的最终通过；用户仍需在T01左右矩形分别停留后确认，核对100×70与“区域”标签。如果仍异常，读取新的`capture.visual`状态继续定位。
