## 阅读摘要

以下为**推断／拟实施范围**；具体指标仍是待验证假设。

| 维度 | 本版结论 |
| --- | --- |
| 用户可见变化 | 在原生窗口／无障碍未提供细目标时，补充有真实矩形边界的视觉区域；保留手动选区、滚轮、确认和输出源。首版不分组无框文字，不自动吸附无owner桌面视觉区域 |
| 决策一 | 先统一 SelectionTarget 并验证原生行为，再接视觉；不把高风险目标重构留到最后（D01、D13） |
| 决策二 | 先对照光标种子扩张 A 与全局候选＋ROI 的 B，再选择算法；同等达标选实体少者。全局通道、候选池不预设必需（D02、D05） |
| 决策三 | 先测 CPU 算法及真实读回成本；CPU 达标就结束后端选型，GPU 只在瓶颈证据充分时进入条件阶段（D04） |
| 风险一 | 纹理／非线性渐变会产生有边但无控件语义的矩形；错吸附率是首要门槛 |
| 风险二 | 小目标、嵌套中层与大目标可能超出某一路发现能力；同一真实集分宿主测召回，不拿合成图代替 |
| 风险三 | GPU 读回／计算与 D2D 争用可能破坏交互；同步 Map 不能随意转移到 worker |
| 阶段门 | P0 分级基线 → P1 统一目标、原生 trace 等价 → P2 CPU 对照与选型报告 → P3 按证据引入图形优化或跳过 → P4 单路径视觉接入与体验验收 → P5 独立验收集、回归及资源全部达标 |

### 1.2 当前相关数据流

**事实**：现有链路由下列代码实现，不含本文提出的视觉分析步骤。

~~~text
CaptureWorker / StartRequest.generation
  -> CaptureProviders::capture[_preserving_color]
  -> FrozenFrame（GPU 纹理，或 BitBlt CPU 像素）
  -> OverlayController::apply_prepared
  -> 渲染冻结背景；CaptureSession 进入 Selecting

WindowTargetProvider -> WindowSnapshot（Z 序、身份、epoch）
  -> hit_test / nearest_target
  -> RefinementScheduler -> RefinementWorker
  -> UIA + MSAA -> DeepTarget / PathLevel
  -> preview_for_cursor -> GestureState / SnapPreview
  -> request_confirm -> apply_confirmation -> CaptureSession::snap_to
  -> CaptureService 从冻结原图读取选区，产生输出
~~~

| 现状（事实） | 代码出处 | 与新链路相关的限制／推断 |
| --- | --- | --- |
| 每次普通截图冻结一个显示器；CapturedFrame 记录尺寸、PixelSource、物理原点 | [S01]：CapturedFrame；[S02]：StartRequest、PreparedFrame；[S03]：apply_prepared | 全局分析指当前冻结显示器，不是重建多屏拼接图；不扩展捕获范围 |
| WGC 路径保留纹理，CPU 像素按需产生；pixels() 缓存整图；read_region() 读取／复制指定区域 | [S04]：FrozenFrame、pixels、read_region；[S05]：capture_monitor、validate_frame_texture | 没有现成整图 CPU 数组可零成本直接交给检测器；产品路径不得未经测量提前物化整图；P2 测试专用全图读回仅用于比较成本 |
| 同一个 D3D11 即时上下文限定单线程调用；同步读回使用 Map，取色块使用非阻塞 Map(DO_NOT_WAIT) | [S06]：owned_context、read_back_pixels、AsyncSampleBuffer::submit/poll | 禁止后台线程操作同一个即时上下文；允许拥有线程提交 GPU 计算，之后异步收取结果 |
| 源像素明确区分 BGRA8/sRGB、RGBA16F/scRGB 等格式与 Alpha；PixelSource 有独立 generation | [S07]：PixelDescriptor、PixelSource、PixelBuffer；[S08]：linear_rgba、to_sdr_bgra8 | 算法必须固定颜色解释，不可把字节布局当作颜色空间；转换不能修改源 |

## 2. 基本事实与推导

### 2.1 不可再还原的事实与硬约束

| 编号 | 基本事实／硬约束（事实） | 依据 |
| --- | --- | --- |
| F01 | 输入是一次冻结的、有限尺寸的颜色采样；分析结果必须对应同一次采样 | [S01] CapturedFrame；[S04] FrozenFrame |
| F02 | 像素只有颜色和位置，不自带“按钮”“容器”等语义；相同像素不能被纯视觉算法区分成不同语义 | 输入数据本质；[S07]；[S25]“功能对照”也明确图像识别不能判断控件类型 |
| F03 | 下游真正需要的是有限个物理像素矩形、包含层级、可确认身份与来源，不需要逐帧整图分割图 | [S14] SnapPreview；[S15] DeepTarget、LevelChain；[S18] prepare_selection |
| F04 | 降采样不可逆：多个不同原图可映射到同一缩图；细线和小区域可能消失 | 采样性质；[S21] scale/refine 的存在也说明缩图坐标不是原图证据 |
| F05 | 清晰填充边界体现为局部颜色跳变；平滑延续的颜色不唯一决定一个矩形；线框可内外同色 | 颜色函数性质；[S24] 图像生成中的 hollow、渐变与填充场景 |
| F06 | 传回 CPU 的数据量等于实际传输字节；3840×2160 的紧排 BGRA8 为 31.64 MiB，FP16 为 63.28 MiB，不含 staging 和副本 | 尺寸×每像素字节；[S07] bytes_per_pixel；不能由此直接推出固定毫秒开销 |
| F07 | 当前产品的 GPU 纹理已用于显示；同一即时上下文只能遵守现有单调用线程约束 | [S04]；[S06] owned_context |
| F08 | 有限资源无法容纳无上限候选、全组合线段配对、无限排队；最坏输入不等于常见桌面 | 有限空间／时间约束；[S02] 容量 1 邮箱；[S15] 单请求在途 |
| F09 | 鼠标查询只需要当前点附近的结果；冻结图不随鼠标移动变化 | [S01]；[S12] hit_test；[S16] update_hover |
| F10 | 异步任务可能在取消、换帧、换窗口、按下鼠标以后完成；不同 generation／epoch 的含义不同 | [S02] generation；[S07] PixelSource；[S11] SnapshotEpoch、RequestGate；[S14] 手势 |
| F11 | 已确认选区、按下时的意图、用户选定层级不能被晚到的自动结果无条件覆盖 | 用户正确性要求；[S14] 手势隔离、[S15] 替换策略是现有部分依据，不代表全部交互已验证 |
| F12 | 颜色值必须结合编码、Alpha 和源快照解释；当前默认是 SDR，HDR 为开发 feature | [S07]、[S08]；README.md“开发”；known-limitations.md“颜色” |
| F13 | 当前窗口数据提供边界和顺序，不包含完整像素遮挡真值；原生控件查询读取活体界面，而图像已冻结 | [S11] WindowCandidate；[S13] 原生查询；[S01] 冻结定义 |
| F14 | CPU、GPU 的速度、驱动开销和共享 GPU 争用取决于设备；当前没有新算法的测量结果 | 本链路未实现；regression-baseline.md“结果记录规则”禁止无测量性能承诺 |
| F15 | 本项目开发期不承担历史兼容，但修改的既有行为必须先固化基线，之后验证全部相关行为 | AGENTS.md §§1～9；用户本次约束 |
| F16 | 本任务要求补充视觉候选，但没有要求 OCR、无边框文本语义分组或所有桌面区域自动识别；纯像素相同可对应不同期望对象 | 用户任务与本次对话；F02。是否扩大范围是产品决定，不能从同类项目功能自动推出 |

### 2.2 关键设计决定

下表均为**推断**；涉及设备收益、参数的部分仍须按“假设”验证。

| 决策 | 设计结论 | 依据 | 可证伪／验收方式 |
| --- | --- | --- | --- |
| D01 | 视觉作为来源，不作为另一个选区状态机；最终统一矩形、来源与包含链 | F02、F03、F11、F15 | 同一事件流无两套预览／确认；T、B 用例检查 |
| D02 | 先对照光标种子扩张 A 与全局＋ROI 的 B；在同样正确性／性能门内优先 A，不预设全局通道 | F03、F04、F08、F09、F14 | P2 同集配对实验；只有可复现召回缺口才保留更复杂方案 |
| D03 | 方向颜色证据、渐变残差和线框成对变化分别验证；不以全框均值／低方差作为硬门槛 | F02、F05、F12 | T02～T07；CPU 数学参考；选择 GPU 后再做数值对照 |
| D04 | 先测 CPU 完整算法、真实全图／ROI／条带读回及交互阻塞；CPU 达标不新增 GPU 计算，图形优化按瓶颈分级 | F06、F07、F14、F15 | P2 决策报告；P3 仅处理已定位瓶颈，同算法 CPU/GPU 对照后保留一个产品路径 |
| D05 | 不复制 mark-shot 的完整 Canny 和重复前景连通域；首版只保留有独立召回贡献的提案 | F03、F05、F08、F15 | 消融实验；缺失召回能定位到具体场景后才增加步骤 |
| D06 | 精修后重算质量；边界缺失、颜色解释不明、精修交叉等情况不得自动采纳 | F01、F04、F05、F12 | T、E 案例检查无虚构分数、无倒置矩形 |
| D07 | 仅为胜出方案保留必要的去重／包含链；真嵌套保留、交叉不冒充父子；不因接近而只按面积比删除层 | F03、F08、F09、F11 | T08、T09、T23；A 的有界链或 B 的至多 320 候选热路径基准 |
| D08 | 原生明确类型含 Text/Image 默认优先；Custom/Unknown 与宽泛容器可视觉细化；桌面无 owner 默认不自动发布 | F02、F03、F13、F16 | §4.6 穷举类型策略与 T11、T20；策略调整用提交与测试体现，不增用户开关 |
| D09 | 分开保存捕获代次、源定义、请求号；窗口 epoch 用于归属绑定，不作为图像内容代次 | F01、F10、F13 | 错代次排列和第二会话测试；静态图像不因刷新窗口而重复检测 |
| D10 | 按下／确认使用冻结的候选记录；已选层级按几何保持，不按新链的数组下标保持 | F10、F11 | B04～B08、T13、T14；迟到事件穷举 |
| D11 | 源只读；所有图形调用遵守 owner；CPU 计算与图形传输分别预算，分析失败不阻塞截图／手动选择 | F01、F07、F10、F15 | 源哈希、故障注入、读回／提交对 UI 的额外耗时；禁止把同步 Map 藏到 worker |

## 4. 算法设计

### 4.1 输入、输出与数据合同

本节为**推断（D01、D06、D09、D11）**；数据合同不预设执行后端。

| 项目 | 定义 |
| --- | --- |
| 图像输入 | 冻结帧的尺寸、PixelSource、ColorSnapshot、显示器物理原点；算法消费有界 CPU 像素视图或选定 GPU 后端的只读纹理，不能重新抓屏 |
| 交互输入 | 当前物理指针、Selecting、停留／手势与手动选层状态 |
| 原生输入 | WindowSnapshot／epoch、原生路径及 LevelKind；无结果或失败有效 |
| 视觉输出 | 原图局部半开矩形与证据；未验证提案不发布；A 输出当前查询的链，B 可输出全局池与当前 ROI |
| 融合输出 | 唯一 SelectionTarget，使用虚拟桌面物理坐标；进入 painter／CaptureSession 时转换一次 |
| 完成状态 | 每批区分 Complete、BudgetExceeded、UnsupportedSource、Cancelled、Failed；Complete 只指已请求覆盖范围，不代表识别出全部语义对象 |
| 来源 | Window、Accessibility、Visual；UIA/MSAA 为无障碍的两种传输 |

~~~text
SelectionTarget:
  rect_screen + origin + owner WindowIdentity（首版自动目标必需）
  capture/source key + ownership_window_epoch
  bounded path of { Rect, origin, optional LevelKind }

VisualCandidate:
  rect_local + four side evidence { support, continuity, fill_jump, stroke, ambiguity }
  provenance（仅保留胜出算法真正使用的来源）

VisualSnapshot:
  capture/source key + request + completion
  query_point（A；仅同点可直接复用链）/ candidate coverage（B）
  validated chain/candidates
  optional global pool（仅 B；A 不预留该字段）
~~~

Window epoch 改变只重新校验归属，不改变冻结视觉几何，也不重新分析全图。Cancelled 批次不能发布；预算不足可保留已验证子集，但必须附不完整状态。桌面无 owner 的默认策略见 §4.6。

### 4.2 备选路线、读回测量与选型门

以下均为**推断／实验方案（D02、D04、D05）**；尚无数据证明哪条路线胜出。推荐先验证最小路线 A，原全局方案降为备选 B。

#### 4.2.1 算法对照

| 方案 | 发现与层级方法 | 可省去的实体 | 具体风险与必要对照 |
| --- | --- | --- | --- |
| A：光标种子＋有界扩张 | 512 ROI 原图中沿多条横纵线找边界峰；组合并验证包围指针的矩形，再逐层外扩；大目标用有界全宽／全高条带补查 | 全局缩图、全屏连通域标签图、全局候选堆／索引；只需有界链和当前覆盖 | 最近边可能是文字笔画／内部图片；光标不在均匀底色、大圆角、断裂边、跨 ROI 与密集嵌套会漏检。单根射线不能证明四边；条带找到边仍须整边验证 |
| B：全局粗检＋原图 ROI | 每源一次有界缩图；连通域／方向线提案；原图验证；当前 ROI 补小目标 | 保留 §4.4 的条件实体，复用全局结果 | 缩图丢细边，连通域丢中层；全局 256 次验证与 CPU/GPU 交接可能不值。必须报告相对 A 新增命中和代价 |
| C：局部起点、按缺口做粗到细扩张 | 仅在 A 的明确失败类型上，在当前窗口／有界更大区域粗查，再回原图验证 | 可能无需全屏常驻池 | 新区域尺度和重算策略会增加实体；只有 A/B 报告均解释不了特定嵌套／大目标缺口时才做测试原型，不预先加入产品 |

A/B 都使用相同的 §4.3／§4.5 边界合同、颜色解释、融合默认值与真值。只比较“最近强边”和完整 B 会混淆提案能力与验证强弱，禁止据此定优劣。测试专用 C 不是必须实施阶段；无独立收益就删除。

#### 4.2.2 P2 的可执行对照

1. 在同一已拥有的 CPU fixture 上做 A/B 标量实现；每次固定指针、窗口／原生输入、目标真值和事件，避免把 provider 波动计入算法差异。P1 的 SelectionTarget 已能承接两类原生来源，P2 仍以离线回放为主。
2. 开发集包含浏览器无障碍开／关、Electron、Qt／自绘、传统原生、Mica／亚克力，交叉深浅主题、DPI、图形类型；测试难例必须包含“光标压在文字上”“大目标边在 ROI 外”“三层中层与外框接触”。数据规范与独立验收集见 §8.2。
3. 逐场景配对记录错误自动吸附、默认目标正确率、候选召回、每条边误差、原生目标被抢占、全局／局部等待、滚轮到目标的步数、CPU／内存／传输；另列模块／类型／缓冲／工具链／独立参数数量与每项必要性。不能用综合分遮盖错吸附。
4. P2 只用开发集作路线选择与阈值校准，配对差异附不确定区间；冻结验收集留到 P5。相同截图多次运行可以测时间，不能增加精度独立样本量。
5. 先检查 §8.4 的安全与精度门，再比较计算／传输预算。A 达精度门且 B 无必需缺口收益就优先 A；B 仅在 A 有必需宿主／中层缺口而 B 能补齐时保留。若均达精度且同样可满足性能，选实体少者；若算法正确但 CPU 性能超门，依据瓶颈进入 §4.2.4 的 P3。若均不达安全／精度门，留在 P2，不用 GPU 掩盖正确性不足。

#### 4.2.3 读回与 CPU 成本必须独立测

**事实**：[S04] read_region 在已有 CPU 像素时裁切复制；否则进入 [S06] read_back_pixels，创建 staging、CopySubresourceRegion、同步 Map(READ)。后者经 owned_context 限定调用线程。把整个 read_region 丢到后台 worker 会违反当前合同，不能作为未经改造即可复用的方案。

| P2 探针 | 必须实测与纳入的开销 | 使用边界 |
| --- | --- | --- |
| 全图读回，4K／8K，SDR／开发 HDR | staging 创建、GPU 排队／copy、Map 等待、行复制、分配、后续 CPU 全链路；31.64/63.28 MiB 只是 4K 紧排数据量 | 测试专用成本上界；不是默认产品路线，完整原图副本计入实际峰值 |
| 单个 512×512 ROI | 同样包含创建／同步／复制，区分首用／复用；SDR 紧排 1 MiB，FP16 2 MiB | owner 读回后把自有字节交 worker；测 owner 的实际事件阻塞，不能只报 worker 计算时间 |
| 全宽／全高条带和批量边样本 | 记录条带次数、总字节、峰值、CPU 拼装与验证；不能将多次小 Map 当免费 | A 大目标的完整成本；条带区域不能补出没有采样证据的整条边 |
| BitBlt／已有 CPU 像素 | 借用与裁切复制成本；源不可变、缓冲生命周期 | 不强制先上传 GPU 再读回；不得借该情况替代 WGC 的读回测量 |
| CPU 计算 | 转色、发现、原图验证、几何／融合分别计时；实际 SIMD／标量方案单列 | 标量 oracle 可留测试，产品只保留胜出实现，不先增加 SIMD 依赖 |

探针在隔离测试入口、正确 owner 线程执行；不得为了测量卡住用户正在使用的捕获窗口。正式交互回放另测 UI／呈现竞争，并包含冷启动与 GPU 忙碌条件。

#### 4.2.4 后端选择，不以 GPU 为前提

| 测量结果 | 决定与下一阶段 | 不新增／删除什么 |
| --- | --- | --- |
| CPU 算法、同步区域传输、UI 与资源均达门 | 选择 CPU，P3 跳过 | 不新增 shader 编译、计算 scratch、计算结果读回；不为“备用”保留 GPU 原型 |
| CPU 计算达标，只有同步 Map 破坏 UI 门 | P3 仅做有界异步 copy／readback，再运行同一 CPU 算法 | 复用 owner 和非阻塞原则；不新增计算着色器。传输与计算是两个决定 |
| CPU 密集计算是瓶颈且算法正确 | P3 实现同算法 GPU 最小原型；真实端到端、资源及 D2D 争用均改善并达门后选 GPU | 不能只以 shader 内核快证明收益；未胜出原型不进产品 |
| 算法本身误检／漏检不达门，或任何后端都超预算 | 留在 P2；减少无收益步骤或正式修订支持范围和验收集版本 | 不以更多线程、缓存、全图副本或 GPU 复杂度覆盖正确性缺口 |

P2 选定算法、CPU基线及是否需P3；P3必要时锁定执行路径。P4不运行A/B或CPU/GPU双产品路径，不保留兼容入口。若 GPU 只在部分设备达标，应缩小资格声明并评估是否改选更普适路径，不能静默建立未经论证的设备分流框架。

### 4.3 共用的方向颜色证据

本节为**推断（D03、D04、D05）**。

- 首版在固定 sRGB 编码的归一化 RGB 上计算方向差异，使用三通道最大幅度；不只取灰度。源为 BGRA 时按通道合同读取，不修改源。
- HDR 路径必须复用固定 ColorSnapshot 和既有色彩映射语义生成分析颜色；所选后端颜色对照不成立前明确 UnsupportedSource。禁止把 FP16 字节直接当八位色，或在不同 ROI 自适应曝光。
- 同时保留普通方向梯度和下面的突变残差。普通梯度提供弱边线索；残差用于渐变抑制。首版不引入全图高斯+Canny 滞后连接；只有消融实验发现独立召回缺口后再论证。

沿候选法线 n、边界中心 p，在同一颜色空间采样 C(-3d)、C(-d)、C(d)、C(3d)，其中坐标代表 p + t×n：

~~~text
g_cross = C(d) - C(-d)
g_outer = C(-d) - C(-3d)
g_inner = C(3d) - C(d)
J(d) = norm_inf(g_cross - (g_outer + g_inner)/2)
~~~

**事实（数学）**：若法线颜色是仿射函数 C(t)=a×t+b，上式 J=0；若边界两侧保留同样背景趋势但产生阶跃 Δ，理想情况下残差为 norm_inf(Δ)。必须先做有符号向量相减，再取幅度。

**假设**：d∈{1,2,4} 个当前分析尺度像素可覆盖细边与一定抗锯齿；非线性渐变、噪声、阴影、色调映射和压缩会破坏理想抵消，仍需原图验证。CPU 与 GPU 都不能跳过这一限制；该公式不提供“所有渐变伪框都能滤除”的保证。

线框单独检查法线上的成对反向梯度：进入描边和离开描边的响应应位置接近、方向相反，沿边厚度大体一致。不能要求线框内外均值不同。最后对横／纵响应做方向非极大值抑制，保留确定性的平局规则。

### 4.4 候选发现：A 的有界链与 B 的条件提案池

本节为**推断（D02、D05、D07、D12）**；只有选中的路线进入产品。

**A 路线**：ROI 内每轮用中心及两侧偏移的有限横纵扫描线取边界峰；保留多个可行峰，组合后必须经 §4.5 四边验证，不能把文字上的第一个峰当对象外沿。首个通过框确定后，从其外侧继续搜索严格包含框；最多沿用 24 个内部层级上限，失败或范围／工作预算耗尽即停。大框外沿先用条带定位，再批量采集四边验证所需区域；不生成全屏密集边图。

扫描线数、每线峰数、每轮组合数、最大扩张轮数／条带总字节均为必要有界量，具体值待 P2 开发集锁定（初始规模和去掉后的问题见 §4.7）。若简单路线要靠接近全图的大量条带才能召回，报告这个事实，不能仍把它称为低成本局部算法。

**B 路线**：冻结背景可显示后每源做一次全局粗检，不能阻塞首显；比例 s=min(1,1280/max(W,H),sqrt(1048576/(W×H)))，各轴按实际尺寸映射。不强制放大短边；面积／低通采样定义必须固定，不能以一次双线性取样冒充任意倍率平均。512 ROI（含 halo）只在 80 ms 停留后且当前覆盖不足时补检；覆盖内查询快照。ROI 人工边不生成候选；大目标交全局或原生。全局和 ROI 复用 scratch。

| B 的提案途径 | 方法与用途 | 必要性／限制 |
| --- | --- | --- |
| 前景边缘连通域 | 对一次半径 1 闭运算后的边缘做一次八邻域连通分析，取外接矩形 | 召回闭合或近闭合控件；不重复 Contour 与 Component 扫描；形态学只生成提案，不能充当原图证据 |
| 背景连通域 | 将边缘作阻隔，四邻域提取背景区域；保留有足够矩形占据率的候选 | 补充面板／分隔区域；占据率阈值需标注集确定，不能默认背景连通即矩形 |
| 方向线段配对 | 扫描非极大抑制后的横纵边；按固定坐标排序，只匹配有重叠区间的有限邻居 | 补充断裂边框／空心框；每条线最多 3 个伙伴，禁止全组合枚举；可能漏掉中间层级，记录并由 ROI／召回集评估 |

B 的 CPU 实现直接处理小图；只有选择 GPU 才由 CPU 接收打包的方向／前景／背景掩码，按通道读取，避免为每个通道再复制一张图。连通域用有上限的标签表和整数外接框；标签超限停止本批提案并标记 BudgetExceeded，不在无界 Vec 上继续增长。

提案入池前检查非空、越界、最小可采样边长、ROI 人工边界。在线去重并用有界堆保留名额；位置网格×面积档只作为排序键，不新建持久空间索引。优先覆盖不同位置和尺度；池满记录丢弃数量，不能只按面积两端截取而丢掉全部中尺度。

近似重复按四边距离和面积接近合并，保留更强的原图证据及所有来源位；不取 union 扩大框。只要边界有可验证差别，嵌套矩形保留。普通 IoU NMS 不适合直接删除所有高重叠父子区域。

### 4.5 共用的原图验证、定位与质量

本节为**推断（D03、D06、D07）**。

1. A的原图ROI／条带只加物理原点；B缩图分别按W/analysis_W、H/analysis_H映射四边并保留误差范围，不共用单轴比例。
2. 对每条边去掉角部约 10% 的区间，再选择最多 64 个不重复原图像素位置。可用位置不足 8 个时不自动采纳；圆角很大导致没有直边的形状属于算法边界。
3. 沿法线计算填充突变、线框支持、有效采样比例、最长连续支持段和最大断裂段。只将有效原图采样计入支持率；读取源外或 ROI 人工边界不得得到固定高分。
4. 小范围搜索四边位置。每轴半径由缩放误差与最大采样偏移推导，初始封顶 16 原图像素；先用最多 16 个位置粗定位，再用最多 64 个位置复核。超出搜索半径不盲目扩大，交由原尺寸 ROI 或拒绝。
5. 先定位左右再定位上下，随后重新验证全部四边。若边交叉、宽高不足、某边变弱或不再包含所需指针，拒绝；不继续发布精修前的旧高分。
6. 原图采样按区域／边批处理；CPU 已拥有像素时直接验证。图形传输必须统计批数，禁止“一条边／一个候选一次同步 Map”。选择 GPU 后才批量在原纹理验证。

**推断／待 P2 固化的定位合同（D06）**：源矩形边界取整数、像素中心取半整数；CPU oracle 与 shader 使用同一采样坐标和插值规则。精修必须把响应峰换算为像素之间的几何边界，不能直接将 texel 下标当右下不含的边。线框的进入／离开峰先归为同一描边，再取其外沿；不能左右两边都简单选“坐标较小的峰”。半像素、奇偶线宽、缩放和取整黄金向量在 P2 锁定；若选 GPU，实际插值误差在 P3 对照；这些规则未固化前不能声称达到 1 px 精度。

**推断／定位验证分层（D03、D06、D13）**：T01 与 T06 的清晰整数边采用逐边 **0 px** 硬断言，专门拒绝系统性偏移和把1px描边内沿当外沿。抗锯齿端到端框采用预标允许区间，Q08当前为覆盖外接框±1px；另将同一底图与固定宽松提案送入 `boundary_location` 阶段，对解析像素覆盖外沿作0px断言，并报告四边有符号误差的均值与最大值。Q08增加跨整数平移；每种输入都返回同一个框不能通过阶段门。该精确覆盖是**合成开发 profile 的定位向量**，不将所有真实宿主的AA边界强行定义为“任一微小非背景像素”。真实图的外沿与允许区间须独立标注；产品采样／取整选择在P2冻结。

候选证据不先压成一个缺少含义的 quality 浮点数：

| 证据 | 用途 | 是否硬门槛 |
| --- | --- | --- |
| 有效来源、尺寸、颜色定义、窗口归属 | 排除不成立的目标 | 是 |
| 四边填充突变或细线支持 | 确认矩形有真实边界 | 是；同一边可由任一模式成立 |
| 支持覆盖、连续性、法线峰位置唯一性 | 排除文字／纹理巧合、确定边界位置 | 是，具体阈值为假设 |
| 框内方差、纹理密度 | 描述内容复杂度 | 首版不新增全框方差；纹理只作局部歧义与排序信号，不因文字／图片直接拒绝 |
| 边界定位误差、最弱边支持、平均支持 | 合格候选间排序 | 排序指标；面积仅在证据相近时作为选取尺度偏好 |

首版采用“通过门槛后按最弱边支持、连续性、歧义、定位误差、稳定几何顺序比较”的确定性排序；不引入学习模型或未经校准的概率分数。高对比纹理仍可能构成真实矩形，像素不能证明其具有控件语义（F02）。

| 渲染回归 | 同设备／负载下呈现间隔 P95 比基线增加≤1 ms；另报卡顿最长区间和 CPU/GPU busy。此门是实测验收，不是调度可硬保证的性质 |
| 算法内存 | 所选产品新增 CPU 缓冲≤16 MiB，GPU 显式资源≤32 MiB；全分辨率额外副本、staging、padding、并存结果均计入；还报告进程／驱动实际峰值 |
| 传输 | A 记录 ROI＋条带＋验证所有读回字节／次数；B 记录全图取得／缩图／验证的所有传输。产品不默认物化完整原图；若 CPU B 必须这么做且突破预算，判不通过，不能把副本排除 |
| 静止／结束 | 无新输入和无在途时新增 dispatch／poll／CPU 图像作业为 0；结束不再发布，重复会话资源不增长 |

**复杂度（推断）**：A 在已拥有 ROI 上的发现约 O(K×(roi_W＋roi_H)×H)，K 为固定扫描线数、H≤24 为层数；再加全部原图验证和条带读取，不能只报射线循环。B 缩图为 O(U)（U 为实际输入读样本数，精确面积滤波可达 O(W×H)）；边缘 O(P)，连通域 O(P×α(P))；找线伙伴保守 O(L²)，去重最坏 O(Q²)。共同精修 O(V×4×S×(2R＋1)×固定采样成本)。候选／链组织放后台；UI读取已发布结果时A为O(W_count＋H)、B为O(W_count＋M)。A的换点种子搜索另算完整CPU查询，不能以读取旧链的时间冒充算法时间；B不能在查询内隐藏O(M²)建链。

**内存核算示例（假设布局）**：A 的 512 SDR ROI 为 1 MiB，条带追加≤1 MiB，再加验证结果、取消交接期间并存缓冲必须逐项计数。B 的 1 Mi 像素图可有 RGBA8 色 4 MiB、方向响应 4 MiB、R8 scratch 两张 2 MiB、打包掩码 4 MiB、staging 4 MiB；CPU 掩码 4 MiB、标签 4 MiB、65536×24 字节标签约 1.5 MiB。仅选择相应后端才分配这些项；ROI／全局串行复用，不为多通道无说明复制全图。

#### 条件性图形执行规则（仅 P3 通过后）

1. 所有 context 调用经 [S06] owner；CPU worker 仅持自有字节与几何。GPU→CPU 传输采用非阻塞完成检查，只在在途时唤醒；需要新计时器必须独立 ID 和停止测试，不照抄取色逐批 Flush。
2. 若只做异步传输，路线是“有界 copy → CPU 算法 → 发布”；只有选择计算后端，才做“GPU 掩码 → CPU 提案 → GPU 原图验证 → 发布”。不能为了适配预建框架强迫 CPU 经过多次 GPU 往返。
3. 计算按有界行块／候选块切片。初始假设单 dispatch 的空闲设备 GPU 时间目标≤1 ms，实测最大值另报；每次 owner 唤醒最多提交一片，下一片等前片完成并让待渲染工作先行，不能一次排满全部片。片尺寸由 P3 在最慢资格设备上测得，halo／分片边缘须做等价断言。
4. 切片不能保证驱动抢占或满载下的绝对时限；若 GPU 忙碌时仍破坏呈现门，就削减分析提交／停止该次视觉资格，并把该负载记为失败或未支持，不能用平均值盖过。资格负载下必须同时满足延迟门和渲染门。
5. 结束解除 SRV/UAV 等分析绑定，不污染 D2D／取色；源只读。取消只撤销发布，GPU 在用资源不可提前复用；保持单批在途，超时后停止新提交，直到安全完成／设备销毁。会话退出不阻塞等 GPU。

| 优先级／指标 | 分子／分母与初始门槛 | 拒绝／遗漏如何计数 |
| --- | --- | --- |
| 第一：无目标误吸附 | 负样本查询中错误发布视觉默认目标／全部负样本查询；单侧95%置信上界≤1% | 原生正常选窗不算视觉误吸附；无框文本、无 owner 桌面和纹理负例必须覆盖。任何一组不达即停，不被别组平均抵消 |

#### 8.4.2 样本下限与置信结论

**事实（数学）**：独立同分布伯努利、零失败、单侧95%时，失败率上界为 1−0.05^(1/n)，成功率下界为 0.05^(1/n)；“3/n”只是近似。由此设下表保守下限，样本量是统计证据要求，不是算法效果已被证明。

| 单项声明 | 零失败时至少采集 | 非零失败／其他限制 |
| --- | --- | --- |
| 默认准确率≥99% | ≥300 个独立且已自动接受的查询 | 按精确单侧 Clopper–Pearson 界判断；300不是允许任意少量失败的固定及格线 |
| 正样本默认成功≥95% | ≥60 个独立清晰正查询，全部成功 | 若有失败，增加样本仍须按冻结采样方案收集并过精确置信门，不得挑容易场景补齐 |
| 无目标误吸附≤1% | ≥300 个独立负查询，零错误发布 | 拒绝正确才是通过；负样本须按事先定义的困难构成采集 |

下限按**每个单独声称合格的宿主／统计总体**计算，不能 H1～H4 共用300却宣称各自99%。同张图的反复运行、相邻点、同页面主题变体不能当独立300份；主要置信样本每个预定义场景簇选一个查询，其余用于稳定性测试，或预先指定簇级统计法。真实采样分布、独立性与跨宿主相关性是待验证假设，不满足时必须收窄置信结论。

若同时宣称 K 个宿主／指标均以整体95%置信达标，预先固定 K 并用每项 α=0.05/K（或预先定义的同等有效校正）；零失败成功门 p 的 n≥ceil(log(α)/log(p))，负例令 p=0.99。300／60只对应单项α=0.05，不能冒充多重声明的联合保证。样本采集量／构成在看验收输出前冻结，禁止边看结果边任意提前停止。未达到数量或界限写“证据不足”，不能只报点估计。

#### 8.4.3 性能、资源与前后对比

P2 开发探针可每场景暖机5次、正式≥100次，只用于 P50/P95／最大值与定位瓶颈；不从100次样本断言稳定P99。P3/P5 的关键设备×分辨率×资格负载至少1000次暖样本、跨至少3个会话；P95为门槛，P99仅在≥1000样本时附原始极值和不确定性作诊断，不新增P99及格门。冷启动另收≥100次独立会话报P95；无 shader 的 CPU 也测首用分配／读回，不能只排除冷启动后宣称首用速度。

CPU wall time、owner 阻塞、GPU 时间戳、呈现间隔分别记录；disjoint／设备错误保留数量、原因和端到端失败，重测不能抹掉失败。原生固定回放与真实 COM 查询分开，A/B 使用同设备／同输入成对比较。GPU 满载必须同时检查总延迟与渲染门，不能只比较 dispatch 内核。

所有选择的后端均做 E15 连续100会话、静止60s，记录分配释放、private bytes／工作集、共享／独占显存峰值。无增长平台与噪声范围由升级前测量定，不随意丢峰。失败／超时／预算溢出计入精度与延迟失败数；未产生可查询结果的样本按超时删失／无穷延迟处理并单报，不能从P95分母删除。
